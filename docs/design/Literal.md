## 字面量
### 整数字面量

整数支持十进制、0b(二进制)、0o(八进制)、0x(十六进制)和类型后缀。

```cns
let decimal = 42;
let binary = 0b101010;
let octal = 0o52;
let hexadecimal = 0x2a;
```

这四个值都是 42，未提供类型注解时都默认为 `i32`。

| 写法 | 可用数字 | 合法例子 | 非法例子及原因 |
| --- | --- | --- | --- |
| 无前缀，十进制 | 0—9 | `42`、`00042`、`010` | `12a`，a 既不是十进制数字，也不是合法后缀 |
| `0b`，二进制 | 0、1 | `0b1010` | `0b102`，2 不是二进制数字 |
| `0o`，八进制 | 0—7 | `0o52` | `0o78`，8 不是八进制数字 |
| `0x`，十六进制 | 0—9、a—f、A—F | `0x2a`、`0x2A` | `0x2g`，g 不是十六进制数字，也不是合法后缀 |

前缀写作小写 `0b/0o/0x`，不写 `0B/0O/0X`。前缀之后必须有数字，裸写 `0x` 不合法。
前导零不改变进制：`010` 是十进制 10，`00042` 是十进制 42。

#### 下划线

下划线只能单个出现在合法数字之间。

```cns
let count = 1_000_000;
let mask = 0b1111_0000u8;
let color = 0x12_ab_34u32;
let permission = 0o7_5_5;
```

| 写法 | 判定 |
| --- | --- |
| `1_000`、`0xff_ffu16` | 合法 |
| `1__000` | 拒绝：两个连续下划线 |
| `1_`、`1_u8` | 拒绝：下划线之后没有紧邻的合法数字 |
| `0x_ff`、`0b_10` | 拒绝：前缀之后不能先写下划线 |
| `_100` | 是名称的写法，不是“带前导分隔符的数字” |

`0xff_ffu16` 中，最后一个 `f` 后直接接 `u16` 后缀，不需要在数字和后缀之间加下划线。

#### 类型后缀

顾名思义

```cns
let a = 42i8;
let b = 42i16;
let c = 42i32;
let d = 42i64;
let e = 42i128;
let f = 42u8;
let g = 42u16;
let h = 42u32;
let i = 42u64;
let j = 42u128;
let k = 42isize;
let l = 42usize;

let bits = 0b101010u8;
let octal = 0o52u16;
let hex = 0x2au32;
```

#### 上下文

无后缀整数字面量可以采用同一表达式中明确的整数上下文。

没有这样的上下文时，普通初始化默认 `i32`；数值太大不会自动升级为 `i64`。

```cns
fn take(value: u8) -> u8 {
    return value;
}

fn large() -> i64 {
    return 2147483648; // 返回类型提供 i64 上下文
}

fn main() -> i32 {
    let a: u8 = 255;    // 注解提供 u8 上下文
    let b = 255u8;      // 后缀直接确定 u8
    let c = 255;        // 普通初始化默认 i32
    let d = take(255);  // 参数提供 u8 上下文
    let e = b + 0;      // 已有 u8 操作数使 0 定型为 u8，结果也是 u8

    // let wrong: u8 = c; // 拒绝：c 已经是 i32
    let narrowed = c as u8;
    return 0;
}
```

#### 最小负整数

负号是运算符，不属于数字文本本身。当一元负号直接作用于整数字面量，
且目标是有符号整数时，允许先结合符号，再检查范围，分组括号不阻断这项规则。

```cns
let a = -128i8;
let b = -(128i8);
let c: i8 = -128;
let d = -32768i16;
let e = -2147483648i32;
let f = -9223372036854775808i64;
let g = -170141183460469231731687303715884105728i128;
```

| 写法 | 判定与原因 |
| --- | --- |
| `128i8` | 拒绝：单独的正字面量越界 |
| `-128i8`、`-(128i8)` | 合法：直接负号与字面量结合后为 -128 |
| `-(128i8 + 0i8)` | 拒绝：负号作用于加法，不能替内部非法的 `128i8` 消除范围义务 |
| `--128i8` | 内层形成 -128；外层是普通取负，产生 `Arithmetic.Overflow` |
| `-1u8` | `1u8` 合法，但无符号非零值取负产生 `Arithmetic.Overflow` |
| `-0u8` | 普通取负得到 0，合法 |

这不是“只要整个表达式的最终值能放下，中途就都允许”的规则。

#### 算术运算

`+`、`-`、`*` 的数学结果必须在操作数类型的范围内，结果类型也必须是操作数的类型。

超出范围产生 `Arithmetic.Overflow`；不是截去高位后继续计算，也不会自动换成更宽类型。

| 表达式 | 规则要求的结果 |
| --- | --- |
| `126i8 + 1i8` | 127i8 |
| `127i8 + 1i8` | `Arithmetic.Overflow` |
| `0u8 - 1u8` | `Arithmetic.Overflow`，不回绕成 255 |
| `20u8 * 12u8` | 240u8 |
| `20u8 * 13u8` | `Arithmetic.Overflow` |
| `-(-127i8)` | 127i8 |
| `-(-128i8)` | `Arithmetic.Overflow` |
| `-1u8` | `Arithmetic.Overflow` |
| `-0u8` | 0u8 |
| `+42u8` | 42u8，类型与值都不变 |

这些规则适用于全部整数宽度，也适用于 `isize/usize`。

要扩大运算范围，先扩大操作数，再做运算：

```cns
let byte = 255u8;
let wide_sum = (byte as u16) + 1u16; // 256u16
// let wrong = (255u8 + 1u8) as u16; // 先做 u8 加法，已溢出
```

中间步骤也必须合法。`(127i8 + 1i8) - 1i8` 在第一步就失败，不会因为最终数学值是 127
而放过中间溢出。

整数 `/` 向零截断：先算商的数学值，再朝 0 丢掉小数部分。

整数 `%` 的余数满足“被除数 = 商 × 除数 + 余数”，非零余数与被除数同号。

| 表达式 | 结果 |
| --- | --- |
| `7i32 / 3i32` | 2 |
| `-7i32 / 3i32` | -2 |
| `7i32 / -3i32` | -2 |
| `-7i32 / -3i32` | 2 |
| `7i32 % 3i32` | 1 |
| `-7i32 % 3i32` | -1 |
| `7i32 % -3i32` | 1 |
| `-7i32 % -3i32` | -1 |

失败边界分别为：

| 条件 | `/` | `%` |
| --- | --- | --- |
| 除数为 0 | `Arithmetic.DivisionByZero` | `Arithmetic.DivisionByZero` |
| 某有符号类型的最小值除以 -1 | `Arithmetic.Overflow`，正数结果无法表示 | 结果为 0，合法 |

例如 `-128i8 / -1i8` 失败，而 `-128i8 % -1i8` 为 0。

#### 位运算

`&`、`|`、`^`、`~` 操作固定宽度的位模式。`^` 是按位异或，不是乘方。

有符号整数采用二进制补码解释位模式。

```cns
let left = 0b1010u8;
let right = 0b1100u8;
assert((left & right) == 0b1000u8); // 8
assert((left | right) == 0b1110u8); // 14
assert((left ^ right) == 0b0110u8); // 6
assert(~left == 245u8);            // 8 位取反：11110101
assert(~0i8 == -1i8);
```

它们不会因为高位为 1 而报告算术溢出；位模式本来就在类型的固定宽度内。
但是两个二元操作数仍须同型，`1u8 & 1u16` 是静态类型错误。

#### 位移

位移左操作数决定结果类型和位宽；右操作数可以是任意内建整数类型，
只要其**数值**满足 `0 <= count < 左操作数位宽`。

```cns
let byte = 1u8;
let count = 3u64;
let shifted = byte << count; // 8u8；计数的类型不必是 u8
```

| 表达式 | 结果或失败 |
| --- | --- |
| `255u8 << 1` | 254u8，超出 8 位的高位丢弃，低位补零 |
| `128u8 << 1` | 0u8，合法，不报告加乘溢出 |
| `64i8 << 1` | -128i8；按 8 位模式移位后再按 i8 解释 |
| `-1i8 << 1` | -2i8 |
| `128u8 >> 7` | 1u8，无符号右移在高位补零 |
| `-3i8 >> 1` | -2i8，有符号右移在高位补符号位 |
| `1u8 << 0` | 1u8 |
| `1u8 << 8`、`1u8 >> 8u128` | `Arithmetic.ShiftCount`，计数等于位宽 |
| `1u8 << -1i32` | `Arithmetic.ShiftCount`，计数为负 |
| `1u8 << 256u64` | `Arithmetic.ShiftCount`，不把 256 截断为 0 |

有符号右移和整数除法不总相同：`-3i8 >> 1` 为 -2，`-3i8 / 2i8` 为 -1。

#### 比较与 bool

整数和浮点都支持同型的 `< <= > >= == !=` 运算，结果是 `bool`。

`bool` 只支持 `!`、`&&`、`||`、`==`、`!=` 运算。

```cns
let count = 3u8;
let positive = count > 0; // 0 在 u8 上下文中形成，positive 是 bool
let enabled = true;
let ready = enabled && positive;
assert(ready);
assert(!false);

// let wrong = 1i8 == 1u8; // 拒绝：同族但不同型
// let wrong = true + 1;   // 拒绝：bool 不能做算术
// let wrong = true < false;
// if (count) {}           // 拒绝：整数不自动解释成真假
if (count != 0) {}         // 合法：显式比较得到 bool
```

`&&` 与 `||` 从左到右短路。左边已经决定结果时，不求右边；但右边的静态类型、名称和字面量资格仍要合法。

链式比较不隐式展开：`a < b < c` 和 `a == b == c` 都拒绝。

要表达区间，写 `a < b && b < c`；若 b 是有副作用的表达式，需要先绑定到局部变量上再进行比较。

### 浮点数字面量

浮点采用十进制，可以写小数、指数和 f32/f64 后缀。

浮点字面量允许按目标精度舍入。舍入到无穷拒绝，舍入到有限值、subnormal 或零允许。

普通浮点运算则可以产生无穷和 NaN。

```cns
let a = 1.0;           // 默认 f64
let b = 0.5;
let c = 1e3;           // 默认 f64，值为 1000.0
let d = 1E+3;          // E 与 e 均可；指数允许正负号
let e = 1.25e-2;       // 十进制的 0.0125，按 f64 形成
let f = 1f32;          // 浮点字面量，不是 i32 转换
let g = 1.0f64;
let h = 1_000.25f32;
let i = 1.2_5e1_0f64;  // 各数字段内部可使用单个下划线
```

如果写了小数点，则两边都必须有数字。

指数标记后必须有数字；若有指数符号，数字跟在符号后。

| 合法写法 | 不合法写法 | 原因 |
| --- | --- | --- |
| `0.5` | `.5` | 小数点左侧缺数字 |
| `1.0` | `1.` | 小数点右侧缺数字 |
| `1.0e2` | `1.e2` | 有指数不代表可以省略小数部分 |
| `1e2`、`1e-2` | `1e`、`1e+` | 指数缺数字 |
| `1.2_5` | `1_.25`、`1._25` | 下划线不能挨着小数点 |
| `1e1_0` | `1_e10`、`1e_10`、`1e+_10` | 下划线不能挨着指数标记或符号 |
| `1f32`、`1.0f64` | `1f16`、`1.0u32` | 不支持 f16；浮点写法不能接整数后缀 |
| `1.0f32` | `0x1.0p0`、`0b1f32` | 不支持非十进制浮点 |

#### 舍入

“舍入”是从精确十进制值中选取一个目标浮点值。采用**舍入到最近值，恰好居中时选偶数**
（roundTiesToEven）：即距离哪一个可表示值更近就选哪一个；距离相同时，选最低有效位为 0 的那个。

这里的“偶数”指二进制有效数字的末位，不是源码小数的末位。

```cns
let tenth = 0.1f32;         // 接受，保存最接近十进制 0.1 的 f32 值
let rounded = 16777217f32;  // 接受，舍入到 16777216
let exact = 16777218f32;    // 接受，这个更大的偶数仍可以精确表示
assert(rounded == 16777216f32);
```

后两个例子说明“超过 16777216 的整数都不能用 f32 表示”是不正确的。
超过这个界限后，能表示的整数开始出现间隔；有些精确，有些需要舍入。

#### 极大、极小的浮点字面量

| 情况 | 规则 | 例子 |
| --- | --- | --- |
| 舍入后为有限值 | 接受 | `0.1f32` |
| 略高于最大有限值，但仍舍入为有限值 | 接受 | 下方的最大值邻近例子 |
| 舍入后为正无穷或负无穷 | 拒绝 | `1e1000f32`、`1e1000f64` |
| 舍入后为次正规非零值 | 接受 | `1.401298464324817e-45f32` 舍入为 f32 最小非零正值 |
| 太小，舍入后为正零 | 接受 | `1e-1000f32` |
| 负号作用于舍入得到的正零 | 得到负零，接受 | `-1e-1000f32` |

f32 最大有限值的精确十进制整数是 `340282346638528859811704183484516925440`。
下面的字面量比它大 1，但按 f32 精度仍舍入到最大有限值，所以允许：

```cns
let rounded_max = 340282346638528859811704183484516925441f32;
```

这不意味着允许使用 `as f32` 转换这个字面量，as操作会检查源值范围，此时已经超出范围，预期失败。

次正规值会继续按同一舍入规则处理，精确值若恰好是最小非零正值的一半，会舍入到正零；

对应负值得到负零。不会因为“结果为零”就把合法浮点字面量当作编译错误。

#### 算数运算

f32/f64 提供 `+ - * /` 和一元 `+ -`。二元操作数必须同型，结果保持该类型。

不提供浮点 `%`、位运算或位移。

```cns
let a = 1.5f32;
let b = 0.5f32;
assert(a + b == 2.0f32);
assert(a - b == 1.0f32);
assert(a * b == 0.75f32);
assert(a / b == 3.0f32);
assert(-b == -0.5f32);
```

每一步按该类型精度舍入，不能把一串运算先以更高精度算完再只舍入一次。

因此数学上可交换分组的表达式，在浮点中未必相同：

```cns
let large = 16777216f32;
let first = (large + 1f32) - large;
let second = large + (1f32 - large);
assert(first == 0f32);
assert(second == 1f32);
```

第一条路径中，`large + 1f32` 的数学结果为 16777217，恰在两个 f32 值中间，
按最近偶数规则舍入回 16777216。后面的减法无法找回已经丢掉的 1。

第二条路径先得到可精确表示的 -16777215，再与 large 相加，得到 1。

Chtholly 不允许为了优化而改变这种逐步舍入：不隐式融合成一次乘加，不开启改变语义的
fast-math，也不把次正规值统一清零。这里的舍入是合法运算结果，不是 `PrecisionLoss` 失败。

### 除零、无穷和 NaN

**浮点除零不是整数除零。** 

普通浮点运算遵守 IEEE 规则，可以产生无穷和 NaN.

| 浮点表达式 | 结果类别 |
| --- | --- |
| `1.0f32 / 0.0f32` | 正无穷 |
| `-1.0f32 / 0.0f32` | 负无穷 |
| `1.0f32 / -0.0f32` | 负无穷 |
| `0.0f32 / 0.0f32` | NaN |
| `1e38f32 * 10f32` | 正无穷，普通运算允许这个结果 |
| 正无穷减正无穷 | NaN |
| 有限非零值除以正无穷 | 相应符号的零 |

```cns
let infinity = 1.0f64 / 0.0f64;
let nan = 0.0f64 / 0.0f64;
assert(infinity > 1e300f64);
assert(nan != nan);
assert(!(nan == nan));
assert(!(nan < 0.0f64));
assert(!(nan >= 0.0f64));
```

只要比较的一方是 NaN，`== < <= > >=` 都是 false，`!=` 是 true。

### 正零与负零

`0.0f32` 与 `-0.0f32` 比较相等，二者都不是非零值；但符号仍能影响后续 IEEE 运算，
例如上面的除零结果。浮点到浮点的转换保留零的符号，转到整数则都得到整数 0。

```cns
assert(0.0f32 == -0.0f32);
let negative_zero = -0.0f32;
let wide_zero = negative_zero as f64; // 仍为负零
let integer_zero = negative_zero as i32;
assert(integer_zero == 0);
```

有限运算的极小结果可以舍入成次正规值或零。

`true`和`false`不会隐式转换成整数参与运算。
